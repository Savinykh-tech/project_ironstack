## 1. Общая информация о проекте

**IronStack** — это портфолио-сайт независимого веб-разработчика, который позиционирует себя как инженер, а не просто "верстальщик". Сайт демонстрирует подход к разработке: чистый код, архитектура, результат.

**Целевая аудитория:**

- Малый и средний бизнес, которому нужен сайт или автоматизация
- Клиенты, уставшие от студий с раздутым штатом и конструкторов вроде Tilda
- Те, кто ценит прозрачность, скорость и юридическую чистоту

**Основные услуги:**

1. Разработка сайтов под ключ (лендинги, корпоративные сайты, интернет-магазины)
2. Автоматизация бизнеса (Telegram-боты, парсеры, интеграции с 1С и CRM)

## ️ 2. Архитектура и технологический стек

### Принцип: "Максимальная простота, максимальная скорость"

Сайт написан на **чистом HTML, CSS и JavaScript (Vanilla)** — без фреймворков, без CMS, без сборщиков. Это осознанное решение, которое демонстрирует сам подход IronStack к разработке.

**Почему так:**

- **Скорость загрузки:** нет тяжёлых библиотек → сайт открывается за 1-2 секунды даже на слабом интернете
- **Независимость:** не нужно платить за подписки (Tilda, WordPress хостинг)
- **Прозрачность:** клиент видит, за что платит — чистый код, который можно передать любому разработчику
- **SEO:** поисковики любят быстрые сайты с чистой семантикой

**Технологии:**

- **HTML5** — семантическая разметка (header, main, section, article, footer)
- **CSS3** — кастомные свойства (переменные), Grid, Flexbox, анимации
- **JavaScript (ES6+)** — нативный JS без jQuery и других библиотек
- **Canvas API** — для анимации звёздного фона (cosmos.js)
- **Git** — контроль версий
- **GitHub** — хостинг кода и портфолио

**Ключевая особенность — CSS-переменные:**
Все цвета, шрифты и размеры вынесены в `variables.css`. Это позволяет:

- Менять дизайн в одном месте (например, сменить акцентный цвет во всём сайте)
- Легко реализовать светлую тему (просто добавить `[data-theme="light"]` блок)
- Поддерживать единообразие дизайна

**Градиентная полоска при наведении:**
Все карточки (услуги, кейсы, принципы) имеют анимированную полоску снизу, которая появляется при наведении. Это фирменная фишка дизайна IronStack.

**sitemap.xml** — XML-файл со списком всех страниц сайта и датами их обновления. Помогает Яндексу и Google быстрее находить новый контент.

## 📝 9. Ключевые решения и их обоснование

### Почему чистый HTML/CSS/JS, а не React/Vue?

**Решение:** Использовать нативные технологии без фреймворков.

**Обоснование:**

- Сайт статичный, не нужен сложный state management
- Меньше кода → быстрее загрузка (критично для SEO)
- Проще поддерживать (не нужно знать фреймворк)
- Демонстрирует навык работы с нативным JS (важно для портфолио)
- Нет зависимостей → нет уязвимостей, нет необходимости обновлять пакеты

### Почему отдельные CSS-файлы для каждой страницы?

**Решение:** Разделить стили по страницам (home.css, about.css, web-dev.css и т.д.).

**Обоснование:**

- Меньше размер CSS-файла на каждой странице (браузер загружает только нужное)
- Проще находить и редактировать стили
- Избегает конфликтов между страницами

**Альтернатива:** Один большой CSS-файл или CSS-модули. Но для текущего размера проекта разделение оптимально.

### Почему Cloudflare для DNS, а не Beget?

**Решение:** Делегировать DNS на Cloudflare.

**Обоснование:**

- Защита от DDoS-атак (бесплатно)
- CDN — кэширование по всему миру (ускорение сайта)
- Бесплатные SSL-сертификаты
- Удобная панель управления DNS
- Аналитика трафика

**Минус:** Нужно вручную добавлять MX-записи для почты (что мы и сделали).

### Почему публичный репозиторий на GitHub?

**Решение:** Сделать код сайта публичным.

**Обоснование:**

- Демонстрирует уровень кода клиентам и работодателям
- Показывает владение Git (стандарт индустрии)
- Бесплатная резервная копия кода
- Возможность collaboration в будущем

**Риски:** Код виден всем. Но для портфолио-сайта это плюс, а не минус.

## Заключение

Проект **IronStack** — это не просто сайт-портфолио, это демонстрация подхода к разработке: чистый код, прозрачность, скорость, юридическая чистота. Все технические решения приняты осознанно, с учётом целей проекта и целевой аудитории.

Сайт готов к запуску после завершения нескольких критических задач (форма обратной связи, деплой, защита от спама). Остальные задачи можно выполнять итеративно, после запуска.
